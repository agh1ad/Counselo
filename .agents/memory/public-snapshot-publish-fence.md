---
name: Public snapshot publication fence
description: Public content is served from object-storage snapshots prepared before a publication epoch becomes active.
---

Public blog, work, legal-update, and approved work-file requests must read only the object-storage snapshot for the active publication epoch. PostgreSQL is reserved for startup or fenced publication prewarming; a missing production snapshot fails closed with a temporary-unavailable response.

**Why:** Allowing a public cache miss to query PostgreSQL made crawler bursts, deployments, and cache-namespace changes expensive and could expose withdrawn content during an incomplete refresh. Rotating the epoch after a zero-row compare-and-swap also makes still-current snapshots unreachable, causing public reads to fail closed.

**How to apply:** Any new anonymous published-content route must consume an epoch-keyed snapshot and be included in publication-time priming. New production processes read the current epoch from Object Storage and never rebuild snapshots from PostgreSQL at startup; missing snapshots fail closed with 503. A guarded write that returns no rows must remove only its own fence without rotating the epoch; real or uncertain writes retain the conservative rotate-and-prime path. If an epoch has already rotated and its active snapshots are missing, reuse a previous complete set only after read-only checks prove no source rows changed (including rows now unpublished), published record/file counts still match, and no fences remain. Copy every public collection and approved-file snapshot to the active epoch; never do this when freshness is uncertain. Validate decoded records rather than the serialized envelope, prime metadata before large document files after mutations, and keep SSR discovery routes from rendering empty fallbacks while snapshots are unavailable. Keep drafts, admin data, contacts, and private files outside this path. Never run a production-mode prewarmer locally against the workspace database: `NODE_ENV=production` does not change `DATABASE_URL`, and could overwrite the shared production snapshot with development data.
